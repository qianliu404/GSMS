## 1. 文档目的与范围

本文档明确系统各角色页面结构、路由、功能点、关键交互、权限控制、异常状态及本地化部署下的交互降级规则，作为前后端开发、UI 设计、测试用例和 UAT 验收的依据。

系统部署于目标机（Windows 11 专业版），Web 管理端通过内网访问（`http://<主机IP>:8080`），必测浏览器为 Microsoft Edge 156，移动端为 H5。企业微信/钉钉/飞书内嵌为后续可选能力，当前版本未接入。

## 4. 通用交互规则

1. **权限驱动**：按钮根据角色、案件成员角色、案件状态、归档状态动态显示；不可用按钮置灰或在后端返回 403/409 并提示原因。
2. **二次确认**：结案、归档、删除案件、永久删除、停用用户、删除流程节点等关键操作需二次确认。
3. **超期提示**：待办、期限、案件列表中超期数据标红/置顶，显示超期天数；支持「已超期 / 临近超期」筛选。
4. **归档只读**：归档案件禁止编辑档案、状态推进、上传文档、分派任务，仅允许查询与受控下载；页面显示「已归档」。
5. **文档访问**：预览/下载统一走 `/api/v1/documents/{id}/preview|download` 鉴权接口，前端不暴露 `E:\GSMS\data\files` 物理路径；水印能力当前未实现（后续规划）。
6. **本地降级**：当前仅站内信通知可用；邮件、企业微信/钉钉/飞书、HR 接口、OA 均为后续可选能力，未启用时不影响核心业务。
7. **列表默认**：按更新时间倒序（台账按发生日期倒序），分页默认 20 条，最大 100 条；支持空状态、加载状态、异常状态。
8. **错误提示**：统一展示错误码与可读信息，如 `40901 状态冲突/非法流转`、`42301 归档案件只读`、`40301 无权限`、`40001 参数格式错误`。
9. **审计留痕**：关键操作成功/失败均记录审计日志；前端不展示敏感字段明文。
10. **浏览器基线**：以 Microsoft Edge 156（Chromium 内核）为唯一必测目标，不依赖 Chrome 专有 API，不提供 IE 兼容方案。
11. **上传上限**：单文件 ≤100MB；当前文档上传为单文件，白名单 `pdf/doc/docx/xls/xlsx/ppt/pptx/jpg/jpeg/png/zip/rar`；须与 Nginx `client_max_body_size`、后端 `max-file-size/max-request-size` 三处一致。
12. **路由刷新**：前端使用 history 模式，Nginx 配置 `try_files $uri $uri/ /index.html`；深链直接访问与刷新不得返回 404。
13. **日期筛选**：GET 查询中的日期统一 `yyyy-MM-dd`（如 `occurDateFrom=2026-11-03`），前端日期组件统一 `value-format="YYYY-MM-DD"`，清空时传空串；格式错误返回 `40001` 并提示按 `yyyy-MM-dd` 输入。
14. **软删除与回收站**：案件、用户删除均为软删除，进入回收站；回收站内「删除」为永久删除，同时清理关联表与磁盘文件，不可恢复。

## 5. 关键页面交互说明

### 5.1 流程总览 `P-DASH-01`

- **路由**：`/dashboard`
- **角色**：除纯审计员外全部用户（按数据范围统计）。
- **布局**：4 张统计卡 + 工伤/仲裁两套流程节点条 + 右侧「待办与预警」列表。
- **统计卡**：在办案件（含工伤/仲裁分项）、节点预警（含超期件数）、本年度已结案（平均办理天数）、累计赔付金额（工伤待遇/仲裁分项）。
- **流程节点条**：按案件类型展示节点名称与当前停留案件数；点击节点跳转 `/cases?type=...&stage=...` 下钻。
- **待办与预警**：列出超期或临期案件节点，显示承办人、超期/剩余天数，点击「办理」进入案件详情。
- **异常**：无数据时展示空态；接口失败展示重试。
- **移动端（≤768px）**：页头标题与日期压紧、两个按钮等分一行（高 34px）；4 张统计卡改 2×2，单卡约 85px、整块约 178px（原各占一行共 456px）；流程节点条、流程说明保持原样（横向滑动查看全部节点）；待办行图标缩至 22px、按钮 28px，两行文字与按钮同行不折行。

### 5.2 案件列表 `P-CASE-01`


- **路由**：`/cases`（可带 `?type=INJURY|ARBITRATION&stage=...`）
- **角色**：管理员、案件管理员、部门负责人、承办人。
- **布局**：页头操作 + 类型分段 + 筛选区 + 表格 + 分页。
- **类型分段**：全部 / 工伤 / 劳动仲裁。**在本页本地筛选**，不跳转到其它模块；从侧栏「工伤案件」「劳动仲裁」进入时携带 `type` 参数并保持分段选中。
- **筛选**：当前阶段、承办人、部门、发生日期范围（`yyyy-MM-dd`）、关键字（案号/当事人）、期限（全部/已超期/临近超期）。
- **表格列**：案号、类型、当事人/部门、当前阶段、流程进度、承办人、发生日期、状态、操作（详情/删除）。
- **交互**：
  - 默认按 `update_time` 倒序。
  - 超期案件行标红并显示超期标识。
  - **不提供批量导出**（导出统一由台账提供）。
  - 删除为软删除，二次确认后进入回收站；已归档案件仅系统管理员可删除。
  - **移动端（≤768px）**：表格改为卡片列表（类型标签 + 案号 + 状态、当事人/部门、阶段序号 + 承办人 + 发生日期、进度条、详情/删除），超期卡片左侧标红条；筛选区仅保留类型分段（满宽三等分）与搜索框，阶段/承办人/部门/日期/期限收进「筛选」开关（有生效条件时显示数量角标，展开后按钮变「收起」并出现「重置筛选」）；分页精简为上一页/页码/下一页。
- **状态**：空列表展示引导；加载中骨架屏；接口异常展示重试。

### 5.3 案件新建 `P-CASE-02`

- **路由**：`/cases/create`
- **角色**：管理员、案件管理员、承办人。
- **布局**：基础信息、组织归属（厂区/车间班组/小班长/大班长）、承办与协作、案件描述、扩展信息分区。
- **必填**：案件类型（工伤 / 劳动仲裁）、案件名称、员工姓名、发生日期、承办人；关联案件、案号、身份证号、案件描述选填。
- **关联案件**：输入案号或当事人远程搜索（案号前缀可命中索引，最多返回 30 条，截断时提示收窄关键字），选中后回显案号/类型/阶段/当事人/承办人/发生日期，并把当事人、厂区、车间班组、班长、承办人、发生日期带入当前表单（可修改）；选中后可填「关联说明」，保存后自动建立两案关联。
- **交互**：
  - 选择案件类型后动态显示工伤扩展（伤害日期/地点/原因/待遇金额/是否争议）或仲裁扩展（仲裁案号/申请日期/开庭时间/裁决金额）。
  - 厂区为字典下拉，可搜索、可直接输入新增，也可点齿轮维护厂区字典；新增后立即可选。
  - 协办人、会签人、阅知人多选，写入案件成员。
  - 案号可自定义（≤32 字符，兼容「（2026）粤0305民初888号」等格式）；留空时按「GY/ZS/GL+年月+4 位流水」自动生成，输入框占位提示当前类型与月份的编号示例。
  - 建档时即初始化法定/内部期限节点；「保存草稿」保持 `DRAFT`，「提交立案」创建后立即流转到 `FILED`。
  - **移动端（≤768px）**：标签改为上置、栅格单列铺满，案件类型为三等分分段控件；「保存草稿 / 提交立案」固定于屏幕底部，长表单任意位置可直接提交；输入字号 16px 避免 iOS 聚焦缩放。
- **异常**：必填缺失定位到字段；自定义案号与已有案号（含回收站）重复时提示「案号已存在」，停留在新建页；留空时编号由 `MAX(seq)+1` 生成，重复提交有幂等提示。

### 5.4 案件详情 `P-CASE-03`

- **路由**：`/cases/:id`
- **办理日期**：当前节点办理区可编辑，默认进入节点当天；修改后截止日期按「办理日期 + 节点时限（工作日）」自动重算，法定节假日不计入、调休上班的周末计入；截止日期仍可人工调整。
- **角色**：案件成员、系统管理员、案件管理员。
- **布局**：
  - 顶部：案号、案件名称、类型与状态标签、当事人、厂区/车间、发生日期、承办人、已办天数；操作按钮（生成文书、主流转动作、已归档占位、删除）。
  - 流程步骤条：按案件类型展示节点，已完成/当前/未开始三态；当前节点显示「截止 MM-DD」并按临近超期（橙）/已超期（红）着色；每个节点下方有「提交」按钮，**仅当前节点可用**，其余置灰。
  - 左主区 7 个 Tab：成员、文档、任务、会签、期限、关联、流转日志。
  - 右栏：当前节点办理卡（结论字段、办理意见、材料上传、主按钮）、档案信息（可编辑，工伤 9 项含休假天数，仲裁含履行款）、期限摘要。
- **交互**：
  - 状态操作按状态机与权限动态显示；非法流转不显示或置灰；主按钮文案随动作变化（立案/推进/结案/归档）。
  - 办理时填写意见与节点结论，提交后写流转日志与审计；支持退回（`ROLLBACK`）。
  - 节点结论随提交回填档案：认定（认定结论）、鉴定（鉴定结论 + **休假天数**）、立案（受理日期）、裁决（结果）、履行（**履行款**，结案时一并写入）。
  - 当前节点办理卡右上角展示「截止 MM-DD · 剩余 N 天」，不足 7 天追加「临近超期」，超期显示「已超期 N 天」。
  - 推进/退回均为「先选目标节点再提交」：推进下拉列出全部可达下游节点（可跳过中间节点，如立案直接到认定），并提示将被跳过的节点；退回下拉列出全部上游节点（可回到更早节点，如争议处理退回立案），默认选中最近的前驱。
  - 结案：需审批权限（案件管理员/部门负责人/管理员），校验状态机允许结案，登记结案方式、卷宗页数、保管年限；结案后统一关闭该案件全部期限节点。
  - 归档：二次确认，归档后全页只读。
  - 成员 Tab 展示负责人、承办人、协办人、会签人、阅知人。
  - 文档 Tab：单文件上传、预览、下载（受控）、版本历史；归档后上传按钮禁用。
  - 任务 Tab：分派任务（类型/责任人/截止/优先级）、完成任务登记结果。
  - 会签 Tab：发起会签、填写意见（同意/不同意/有条件同意）。
  - 期限 Tab：展示节点、类型、剩余天数、状态；可登记超期原因、督办、完成。
  - 关联 Tab：按案号建立/解除关联（仅需案号与说明，不再区分关联类型），聚合查看关联案件；集中管理入口为「争议关联」页。
  - 流转日志 Tab：时间轴展示每次流转的前后状态、动作、操作人、意见，退回动作单独标识。
- **异常**：非案件成员返回 40301；归档编辑返回 42301/40901。
- **移动端（≤768px）**：案号独占一行，类型/状态/当前节点标签紧随其后；操作按钮为主操作整行置顶（结案/归档类主操作在窄屏隐藏，统一走下方「当前节点办理」入口）+ 退回/生成文书/删除三等分一行；基础信息改两列上下排（长值最多两行）；步骤条节点压缩至 66px 并隐藏滚动条，进入页面自动把当前节点滚到可视区中间；「当前节点办理」的退回与保存草稿等宽同行、主操作独占一行；档案信息由 4 列网格改为单列行式（标签左、值右，约 36px/行）；Tab 内表格保留横向滑动，字号与内边距缩小。

### 5.5 台账 `P-LEDGER-01`

- **路由**：`/ledger`
- **角色**：系统管理员、案件管理员（其余角色可在用户与角色中另行授权）。
- **布局**：4 张统计卡 + 类型分段 + 筛选 + 字段设置 + 导出台账 + 表格。
- **视图**：类型分段「全部 / 工伤 / 劳动仲裁」切换案件范围；三个视图的数据筛选与显示字段相互隔离。
- **字段设置**：弹窗内选择配置范围（全部 / 工伤 / 劳动仲裁），三套勾选分别保存在本地，修改其中一套不影响其它两套；工伤范围不展示仲裁专属字段，仲裁范围不展示工伤专属字段，序号列固定。
- **可选字段（27 项）**：序号、类型、案号、厂区、车间班组/部门、姓名、发生日期、案件描述、受伤原因及日期、争议事由、工伤认定情况、劳动能力鉴定结论、休假天数、一次性伤残金/医疗金/就业金申领、仲裁案号、申请日期、受理日期、开庭时间、结案方式、裁决/调解金额、履行状态、履行款、承办人、当前状态、结案日期。
- **业务交互**：工伤视图下点击三项申领标签可推进进度（未申领 → 申领中 → 已到账），与「待遇处理」节点联动。
- **导出**：`GET /api/v1/ledger/export?columns=...`，导出表头、顺序与当前视图表格列完全一致，并保留筛选条件、数据权限与导出人留痕。
- **异常**：无权限查看金额时金额列不返回明细；无匹配数据时统计卡为 0、表格空态。
- **移动端（≤768px）**：4 张统计卡改 2×2；筛选区保留类型分段与搜索，厂区/认定/申领收进「筛选」开关（带生效数量角标，展开后出现「重置筛选」）；23 列宽表改为卡片——常显类型/案号/姓名/厂区班组/当前状态/认定/鉴定，三项待遇各一行（点标签仍可更新进度），其余可见字段点「展开 N 项字段」查看；分页精简为上一页/页码/下一页。

### 5.11 流程节点配置 `P-SYS-02`

- **路由**：`/system/workflow`
- **角色**：系统管理员。
- **布局**：工伤/仲裁两张流程卡，含流程图预览与节点表格。
- **表格列**：序号、节点名称、状态码、办理时限、主责角色、关键材料/输出文书、系统动作、后继节点、回流、状态（启用开关）、操作。
- **规则**：
  - 新增节点自动接在前驱与原后继之间（前驱 → 新节点 → 原后继），插入位置不能落在「归档」之后。
  - 删除节点由前驱接续被删节点的后继；分支节点只摘除被删的那一条；重连结果与内置拓扑等价时回落内置流程。
  - 后继必须同流程、不可指向自身、不可成环（保存时 DFS 检测）。
  - 首末节点（草稿/归档）不可删除、不可停用；有在办案件或会使前驱无出路的节点不可停用。
  - 停用节点不再出现在可流转目标中，历史停留在该节点的案件进度做兜底展示。
  - 所有节点变更写入审计日志。
- **异常**：状态码重复、成环、删除终态节点等均返回明确提示。

### 5.15 角色权限 `P-SYS-04`

- **路由**：`/system/permissions`
- **角色**：仅系统管理员（菜单 `P-SYS-04` 只授权给 `ROLE_SYS_ADMIN`）。
- **布局**：顶部操作条（选择角色 / 数据范围只读回显 / 保存权限 / 新建角色）+ 按模块分组的权限勾选卡片（卡片头显示「模块名 已选/总数」，右上角「全选 / 清空」）。
- **权限粒度**：13 个模块 × 查看 / 新增 / 编辑 / 删除，另含导出、推进、批量导入等动作，共 37 个权限点；勾选状态来自 `sys_role_permission`，保存为全量覆盖。
- **交互**：
  - 切换角色即加载该角色已授权项；未保存前切换会有丢失提示。
  - 「保存权限」提交该角色全量权限并写审计；**已登录用户需重新登录或刷新令牌后生效**（权限随 JWT 下发）。
  - 「新建角色」：填写角色编码（自动加 `ROLE_CUSTOM_` 前缀）与角色名称，创建后默认无权限，需再勾选保存。
  - 「删除角色」：仅非 `ROLE_SYS_ADMIN` 可删，二次确认后同步解除用户挂载、清理权限与菜单授权并写审计。
  - 数据范围（全部 / 本部门 / 本人）由「用户与角色」页维护，与本页的功能权限互不影响。
