## 1. 引言

### 1.1 编写目的

本文档依据《系统定位》文件及本地化部署要求，明确“工伤与劳动仲裁案件协同管理系统”的业务需求、功能需求、非功能需求、接口需求、本地部署需求及验收标准，作为系统设计、开发、测试、本地部署和验收的依据。

### 1.2 项目背景

企业当前工伤和劳动仲裁案件分散管理，缺乏统一入口和流程约束，跨部门协同效率低，期限预警缺失，文档版本混乱，审计追溯困难。为提升案件管理规范化、协同化和数字化水平，建设本系统，并要求系统可在本地服务器和内网环境部署运行。

### 1.3 项目范围

本系统为企业内部案件协同管理平台，部署于企业本地服务器或内网环境，覆盖工伤案件、劳动仲裁案件及关联争议案件的全生命周期管理，实现案件统一建档、状态跟踪、跨部门协同、文档管理、期限预警、报表分析和审计留痕。核心功能不依赖外部公有云。

### 1.4 术语定义

| 术语         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 工伤案件     | 员工在工作过程中发生伤害，按法定程序进行工伤认定、鉴定、待遇处理等案件 |
| 劳动仲裁案件 | 企业与员工之间因劳动关系产生的争议，提交劳动仲裁委员会处理的案件 |
| 关联争议案件 | 与工伤或仲裁案件相关联的其他争议案件                         |
| 闭环管理     | 登记→分派→办理→审批→预警→结案→归档→分析的全流程管理          |
| RBAC         | 基于角色的访问控制                                           |
| 工作流引擎   | 支撑流程定义、流转、审批、会签的引擎                         |
| 会签         | 多个部门或角色对同一事项分别签署意见的审批方式               |
| 水印         | 文档预览/下载时叠加用户名、时间、案件编号的标识（后续规划）  |
| 本地化部署   | 系统部署在企业自有服务器或内网，数据不出内网，外部集成可选   |
| 可选集成     | HR/OA/IM/ES/MQ/MinIO 等通过配置开关启用，关闭后核心业务可用  |

### 1.5 参考文档

- 《系统定位》文件

- 本地服务器、内网部署与备份恢复规范

## 2. 总体描述

### 2.1 产品定位

系统定位为企业内部案件协同管理平台，部署于本地服务器/内网，覆盖工伤案件、劳动仲裁案件及关联争议案件的全生命周期管理，实现案件统一建档、状态跟踪、跨部门协同、文档管理、期限预警、报表分析和审计留痕。

### 2.2 建设原则

1. **统一入口**：所有工伤和仲裁案件统一平台登记、办理、归档。
2. **流程可控**：关键状态变更、审批、会签、结案均有规则约束。
3. **本地可控**：核心数据、文档、日志存储在本地或内网，外部集成可关闭。
4. **最小依赖**：默认 MySQL + 本地文件存储 + Nginx 即可运行核心业务。

### 2.3 总体目标

建设一套覆盖工伤案件和劳动仲裁案件全生命周期的内部协同管理系统，实现案件“登记—分派—办理—审批—预警—结案—归档—分析”的闭环管理，并支持本地化部署、内网访问、本地备份与恢复。

### 2.4 用户角色

| 角色       | 职责说明                                         |
| ---------- | ------------------------------------------------ |
| 系统管理员 | 系统配置、用户与角色管理、流程节点配置、审计日志查看 |
| 案件管理员 | 案件全局管理、案件分派、结案归档审核             |
| 部门负责人 | 本部门案件审批、督办、查看本部门报表             |
| 承办人     | 案件具体办理、状态推进、文档上传、任务分派       |
| 协办人     | 协助办理、查看案件、上传材料                     |
| 会签人     | 在会签节点签署意见                               |
| 阅知人     | 只读查看案件信息                                 |
| 审计员     | 审计日志查询与导出                               |

> **角色可维护**：内置 8 个角色作为初始模板，系统管理员可在「角色权限」页**自定义新建、删除角色**（系统管理员角色不可删除）；每个角色按「模块 × 操作」授权，见 3.6.2。

### 2.5 运行环境

- **部署环境**：企业本地服务器（目标机 `ZJDL-20231109KQ`，Windows 11 专业版，i5-12400 / 8GB 内存），采用 **JAR + Nginx** 传统部署。目标机未安装 Docker，Docker Compose 部署方式不适用。
- **运行支撑**：JDK 1.8.0_391、MySQL 8.0.45（本机已安装，端口 3306，服务名 `MySQL80`）、**Nginx 已安装并运行于 8080**（80/443 被系统进程占用，8443 预留给 HTTPS）。
- **服务端口**：后端 `8089`（配置项 `APP_PORT`，避免与宿主 `SERVER_PORT` 冲突）、Nginx `8080`、前端 Vite 预览 `4173`（仅开发/演示）。
- **Web管理端**：必测 **Microsoft Edge 156**（目标机唯一浏览器）；Chrome、Firefox、Safari 在外部终端可用时补充验证，通过内网访问。
- **移动端**：H5 内网访问（`/m/todos`）；企业微信/钉钉/飞书内嵌为后续可选。
- **存储目录**：数据库备份、文档、日志、临时文件统一存放 `E:/GSMS/data`（C 盘剩余不足 15GB，不作数据盘）；文档根目录 `E:/GSMS/data/files`。
- **生产服务器**：`192.168.11.179`（Windows Server 2016 / 8C16G / 仅 C 盘），JDK 1.8.0_231 + MySQL 5.7.11 + Nginx 1.22，对外端口 `8081`，后端 `8089` 仅本机监听，数据目录 `C:\GSMS`；详见开发文档 9.1。
- **集成环境**：当前仅站内信通知可用；邮件、HR 接口、OA、企业微信/钉钉/飞书均为后续可选，未启用不影响核心业务。

### 2.6 设计约束

- 系统需符合企业信息安全要求，数据默认不出内网。
- 关键状态变更、审批、会签、结案必须有规则约束。
- 全操作留痕，审计日志默认保存 1 年，超期记录由定时任务自动清理（保留年限可配置，见 3.6.4）。
- 文档预览/下载需做权限校验；文档默认且仅存储于本地磁盘 `E:/GSMS/data/files`。
- 外部集成必须通过配置开关启用，关闭后不影响核心案件业务。
- 支持本地备份与恢复，提供初始化 SQL、配置模板和部署说明。

## 3. 功能需求

### 3.1 案件中心

#### 3.1.1 案件建档

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 支持工伤案件、劳动仲裁案件两类建档，完成案件基础信息与扩展信息登记；关联争议不再单独建档，改为在「争议关联」中把已建案件关联起来。 |
| 优先级   | 高                                                           |
| 输入     | 案件类型（工伤 / 劳动仲裁）、关联案件与关联说明（选填）、案号（选填，可自定义）、案件名称、员工姓名、身份证号（选填）、发生日期、厂区、车间班组、小班长、大班长、案件描述（选填）、承办人、协办人/会签人/阅知人、附件；工伤扩展（伤害日期/地点/原因/待遇金额/是否争议）或仲裁扩展（仲裁案号/申请日期/开庭时间/裁决金额） |
| 处理规则 | 1. 必填项：案件类型、案件名称、员工姓名、发生日期、承办人；2. 厂区取自 `plant_area` 字典，支持搜索、直接输入新增与字典维护；3. 部门由承办人所属部门自动带出，不再要求手工填写；4. 支持保存草稿（`DRAFT`）；5. 案号支持立案时自定义（≤32 字符，不强制系统前缀，兼容「（2026）粤0305民初888号」等历史/仲裁编号），留空则按 `MAX(seq)+1` 自动生成（GY/ZS/GL+年月+流水）；自定义案号与系统内已有案号（含回收站）重复时拒绝并提示；6. 建档即初始化法定/内部期限节点；保存草稿为 `DRAFT`，提交立案则流转至 `FILED`；7. 选择「关联案件」后自动带入该案件的当事人、厂区、车间班组、班长、承办人与发生日期（可再修改），并可填写「关联说明」；保存时自动建立两案关联；8. 关联案件采用远程搜索（案号前缀 + 姓名/名称匹配，单次最多 30 条，结果截断时提示收窄关键字）；9. 附件上传至本地磁盘。 |
| 输出     | 案件记录、案件编号、案件成员、期限节点、操作日志                 |
| 验收标准 | 三类案件均可成功建档；必填校验有效；草稿可恢复；立案后案件编号唯一；自定义案号保存后原样显示且重复被拦截；留空时自动编号；厂区新增后立即可选；无 HR 接口时手动录入仍可建档。 |

#### 3.1.2 案件状态跟踪

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 按状态机跟踪案件全生命周期状态，记录状态变更历史。           |
| 优先级   | 高                                                           |
| 输入     | 状态变更动作、操作意见、操作人                               |
| 处理规则 | 1. 状态流转受状态机约束；2. 关键状态变更触发审批或会签；3. 每次变更记录操作人、时间、前后状态、意见；4. 非法流转拒绝并提示。 |
| 输出     | 最新状态、状态流转日志                                       |
| 验收标准 | 状态流转符合状态机；关键节点触发审批/会签；流转日志完整可查。 |

#### 3.1.3 案件关联

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 「争议关联」集中管理已建案件之间的关联关系（如工伤转仲裁、待遇争议关联），支持新建案件时带关联、关联页集中查看与解除、清单导出。 |
| 优先级   | 中                                                           |
| 输入     | 主案案号、关联案案号、关联说明                               |
| 处理规则 | 1. 关联为双向，按「案件对」去重展示，主案取先建档的一方；2. 关联页提供关联关系数、进行中关联（至少一案未结案）、关联当事人（去重人数）三项统计；3. 列表按案件类型与关键字（案号/当事人）筛选，可按当前条件导出清单；4. 解除关联需可访问该案件，解除后两侧同时失效；5. 同一对案件不可重复关联。 |
| 输出     | 关联关系记录、关联案件视图、关联清单（Excel）                |
| 验收标准 | 可建立/解除关联；关联案件可聚合查看；操作留痕。              |

#### 3.1.4 结案与归档

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 对满足条件的案件执行结案与归档，归档后案件只读。             |
| 优先级   | 高                                                           |
| 输入     | 结案意见、结案方式、卷宗页数、保管期限、归档确认             |
| 处理规则 | 1. 结案需具备审批权限（案件管理员、部门负责人、系统管理员），且状态机允许进入 `CLOSED`；2. 结案时统一关闭该案件全部期限节点，超期数量先留痕再关闭，避免案件卡在最后一步；3. 结案写入结案日期、结案方式、卷宗页数与保管年限；4. 归档需二次确认，`archive_status=1` 后禁止编辑、推进、上传与分派，仅允许查询与受控下载；5. 归档库支持按类型/年度/关键字检索与卷宗目录导出。 |
| 输出     | 结案状态、归档信息、流转日志、审计日志                       |
| 验收标准 | 无审批权限不可结案；非法状态不可结案；结案后期限节点全部关闭；归档后不可编辑；归档库可按条件检索并导出。 |

> **后续规划**：多级结案审批流、归档借阅审批（含借阅期限与归还）当前未实现，不在本期验收范围。

### 3.2 协同中心

#### 3.2.1 任务分派

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 承办人可将案件任务分派给协办人/部门，并跟踪任务完成情况。    |
| 优先级   | 高                                                           |
| 输入     | 任务类型、责任人、截止时间、优先级、任务说明                 |
| 处理规则 | 1. 仅案件负责人/承办人可分派；2. 分派后通过站内信/邮件通知，IM 通知可选；3. 任务超期标红；4. 任务完成需登记结果。 |
| 输出     | 任务记录、通知记录                                           |
| 验收标准 | 任务可分派并通知；责任人可在待办中看到；超期可识别；关闭 IM 时站内信/邮件仍可用。 |

#### 3.2.2 待办中心

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 汇总个人待办理任务、待会签记录、临期/超期期限节点。           |
| 优先级   | 高                                                           |
| 输入     | 当前用户、类型筛选                                           |
| 处理规则 | 1. 三类待办统一汇总：待办理（TASK）、待会签（COUNTERSIGN）、期限（DEADLINE）；2. 超期项置顶并标红，显示超期天数；3. 支持跳转案件详情对应 Tab 或期限中心处理；4. 提供三类数量统计；5. 移动端 `/m/todos` 提供精简列表。 |
| 输出     | 待办列表、数量统计                                           |
| 验收标准 | 三类待办准确聚合；超期标识明显；可跳转处理；统计数量与列表一致。 |

#### 3.2.3 会签

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 关键节点支持多部门/多角色会签，记录会签意见。                 |
| 优先级   | 高                                                           |
| 输入     | 会签人、会签意见（同意/不同意/有条件同意）、意见说明         |
| 处理规则 | 1. 会签人由案件成员中的会签角色或发起时指定；2. 会签意见必填；3. 会签记录写入数据库并生成待会签待办；4. 会签结果在案件详情会签 Tab 汇总展示。 |
| 输出     | 会签记录、待办                                             |
| 验收标准 | 会签人可收到待办；意见可记录并展示；重复会签有提示。         |

> **后续规划**：按「全部同意 / 比例同意 / 指定角色同意」自动判定会签完成并驱动流转，当前版本仅记录意见，不做自动判定。

### 3.3 文档中心

#### 3.3.1 证据材料管理

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 功能描述 | 按案件分类管理证据材料，支持上传、预览、下载、版本查看。     |
| 优先级   | 高                                                           |

### 3.6 系统管理

#### 3.6.1 组织与用户

- 支持部门维护（页面新增）、用户新增/编辑、角色分配、启用/停用、重置密码。
- 用户删除为**软删除**，进入回收站；内置 `admin`、当前登录账号、最后一个系统管理员、仍在办案件的承办人不可删除。
- 停用账号立即无法登录；历史案件、审计记录保留。
- HR 接口同步未启用，人员由页面维护。

#### 3.6.2 RBAC 权限

- 内置角色 8 个：系统管理员、案件管理员、部门负责人、承办人、协办人、会签人、阅知人、审计员；数据范围 ALL/DEPT/SELF。
- **功能权限按「模块 × 操作」细分**：13 个业务模块，按查看 / 新增 / 编辑 / 删除（含导出、推进、批量导入等动作）共 37 个权限点，存于 `sys_permission` 与 `sys_role_permission`。
- **角色自定义**：系统管理员角色（`ROLE_SYS_ADMIN`）不可删除，其余角色可在「角色权限」页新建（`ROLE_CUSTOM_` 前缀）与删除；删除时同步解除用户挂载、清理授权与菜单并写审计。
- 权限双端生效：后端接口以 `@PreAuthorize("hasAuthority('模块:操作')")` 强制校验，权限随 JWT `perms` 声明下发；前端按权限隐藏无权限的菜单、按钮与操作列。
- 菜单权限、按钮权限另由 `sys_menu`/`sys_role_menu` 控制；接口层结合数据权限校验。
- 案件成员权限：负责人、承办人、协办人、会签人、阅知人。
- 字段级控制：身份证号 AES 加密后脱敏展示；姓名按权限脱敏；金额按权限决定是否下发。

#### 3.6.3 工作流与节点配置

- 采用**自研状态机**（`CaseStateMachine`）+ 节点定义表（`wf_node_def`），未引入 Flowable。
- 工伤、仲裁各自独立拓扑，仲裁含「裁决 → 履行 / 上诉」分支；推进与退回均支持自选目标节点（推进可跳过中间节点，退回可回到更早节点）。
- 每个节点按配置时限（工作日）推算截止日期，进入节点即生成期限记录；截止日前 7 个自然日提醒，不足 7 天为临近超期。
- 节点配置：增删改、调序、后继配置、启用/停用；
- **推送设置**：按周期（每天/每周/每月）与指定日期时间推送；推送字段可自定义；推送条件可自定义——16 个字段（案号、案件类型、状态、节点、承办人、厂区、是否已开启计时、剩余天数等）+ 操作符（等于/包含/属于/大于/小于等）自由组合，多条同时满足才推送，条件可持续扩展；同一配置每天仅推送一次（手动测试不计入），到点后 30 分钟内可补推；无符合条件数据时不推送；消息以表格样式图片发送，字段多时图片宽度自适应放大、单元格内容过长自动换行，保证内容完整可读，支持发送前实时预览图片、测试推送、查看推送历史。
新增自动接链、删除自动重连、成环校验；首末节点不可删除/停用；变更写审计日志。
- **办理日期**：当前节点办理区显示办理日期，默认为进入节点当天且可修改；截止日期按「办理日期 + 节点时限（工作日）」计算，法定节假日顺延、调休上班的周末计入；人工调整截止日期仍保留。
- 流程实例表 `wf_instance` 记录案件流程实例，可在流程配置页查看；多版本流程定义与运行中实例干预（转办、加签）当前未实现。

#### 3.6.4 审计日志

- 记录登录、查询、新增、修改、删除、状态流转、结案归档、文档访问、导出、权限变更、流程节点变更等操作。
- 日志不可篡改，按关键字/模块/结果/时间检索，参数脱敏展示。
- 默认保存 1 年（配置项 `gsms.audit.retention-years`，环境变量 `AUDIT_RETENTION_YEARS`）；每天 02:30 定时清理超期记录，服务启动时补做一次，按 1000 条/批删除。
- 当前不提供导出；保留年限可按企业制度调整。

#### 3.6.5 消息通知

- 当前仅站内信（`notification.channel=INNER`），支持未读数、单条已读、全部已读。
- 邮件、企业微信/钉钉/飞书、短信为后续可选，`channel` 字段已预留。

## 7. 验收标准

### 7.1 功能验收

- 工伤案件、劳动仲裁案件均可完成建档、流转、结案、归档；历史遗留的关联争议案件保留只读办理能力，新案件不再按该类型建档。
- 建档必填校验有效；厂区字典可新增并即时生效；草稿可保存；立案后编号唯一。
- 状态机按案件类型生效，仲裁「裁决 → 履行/上诉」分支可正常流转；退回功能可用。
- 结案需审批权限，结案后期限节点全部关闭；归档后只读。
- 待办（待办理/待会签/期限）、任务分派、会签记录正常。
- 文档上传、预览、下载、版本历史、权限控制正常（水印不在本期验收）。
- 期限初始化、扫描、超期升级、原因登记、督办、完成正常。
- 台账覆盖工伤与仲裁，三套字段配置互相隔离，导出列与页面一致。
- 归档库检索、卷宗详情、卷宗目录导出正常。
- 回收站支持案件/用户恢复、永久删除、批量操作，永久删除后无残留。
- 报表统计准确，工伤统计表可导出且带导出人留痕。

## 8. 附录

### 8.1 工伤案件状态机

```text
草稿(DRAFT) → 立案(FILED) → 调查取证(INVESTIGATION) → 申报(DECLARE)
→ 认定(RECOGNITION) → 鉴定(APPRAISAL) → 待遇处理(TREATMENT)
→ 争议处理(DISPUTE) → 结案(CLOSED) → 归档(ARCHIVED)
```

- 主链之外允许 `TREATMENT → CLOSED` 直接结案（无争议情形）。
- 关键节点支持退回至上一节点（`ROLLBACK`，归档节点不可退回）。
- 认定、鉴定、待遇处理节点支持会签记录。
- 鉴定节点登记伤残等级与**休假天数**，办结后回填案件档案。
- 结案需审批权限；归档需二次确认。

### 8.2 劳动仲裁案件状态机

```text
草稿(DRAFT) → 立案(FILED) → 证据准备(EVIDENCE) → 开庭(HEARING)
→ 裁决(AWARD) / 调解(MEDIATION)
→ 履行(PERFORM) → 结案(CLOSED) → 归档(ARCHIVED)

上诉分支：裁决(AWARD) → 上诉(APPEAL) → 开庭（二审）(RETRIAL_HEARING) → 裁定(RULING) → 履行(PERFORM) → 结案(CLOSED)
```

- 开庭后按结果分支至裁决或调解；裁决后可履行或上诉；裁定后同样必须进入履行，履行完毕才能结案。
- 调解可直接进入履行或结案。
- 履行节点可登记履行状态、**履行款**与完成日期，结案时履行款一并写入档案。
- 结案需审批权限；归档需二次确认。
