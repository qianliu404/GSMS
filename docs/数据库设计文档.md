## 2. 设计原则与约定

1. **数据库**：MySQL 8.0.45，InnoDB，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`；业务库名为 `case_system`（测试库 `case_system_test`，恢复演练库 `case_system_restore`）。
2. **连接参数**：JDBC URL 必须带 `characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true`（目标机时区为 China Standard Time，MySQL 服务端默认时区为系统时区，客户端与服务端须显式对齐，避免 `create_time` 偏移 8 小时）。
3. **账号隔离**：应用使用专用账号 `case_app`，仅授予 `case_system` 库的 DML/DDL 权限，禁止应用侧使用 root 连接。
4. **主键**：业务表统一使用 `bigint` 自增主键；业务编号如 `case_no` 单独唯一索引。
5. **逻辑删除**：核心业务表使用 `deleted tinyint default 0`，不物理删除；审计日志、状态流转日志、会签记录、文档版本不可物理删除。
6. **时间字段**：统一 `create_time`、`update_time`；业务操作时间单独记录，如 `operate_time`、`upload_time`、`countersign_time`。
7. **敏感字段**：身份证号 AES-256-GCM 加密存储；员工姓名按权限脱敏；待遇金额、裁决/调解金额等 `decimal` 字段明文存储（需参与 SUM 统计），由接口层按权限决定是否下发；审计日志记录脱敏值。
8. **本地文件存储**：`case_document.file_path` 默认保存本地相对路径，如 `/files/2026/11/xxx.pdf`（物理根目录 `E:\GSMS\data\files`）；启用 MinIO 时保存对象 Key。
9. **可选组件**：Redis、Elasticsearch、RabbitMQ、MinIO 不改变核心表结构；当前均未启用，审计检索使用 MySQL。
10. **数据权限**：案件数据权限通过 `case_main.owner_id`、`handler_id`、`department_id` 与 `case_member` 联合控制。
11. **审计要求**：登录、查询、新增、修改、删除、状态流转、审批、会签、文档上传/预览/下载、导出、权限变更、流程干预均写入 `audit_log`，默认保留 1 年（可配置）。
12. **备份要求**：MySQL 与本地文档目录每日备份至 `E:\GSMS\data\backup`，备份文件加密，定期恢复演练。
13. **性能基线**：目标机 `innodb_buffer_pool_size` 当前仅 128MB、`max_connections=151`。上线前应将缓冲池调整为 2GB（`my.ini` → 重启 `MySQL80` 服务）；连接池上限（Druid `maxActive`）建议 20，勿超过 `max_connections` 的 1/5，以免与同机其他库争用连接。

## 7. 敏感字段与数据权限

1. **加密存储**：`case_main.id_card_no` 使用 AES-256-GCM 加密（密钥来自 `CRYPTO_SECRET`），读取时解密后再按权限脱敏展示。
2. **脱敏展示**：`employee_name` 在无敏感字段权限时按「张*」形式脱敏；身份证号默认掩码展示（如 `4401**********1234`）。
3. **金额字段**：`treatment_amount`、`award_amount`、三项 `subsidy_*_amount` 为 `decimal(14,2)` **明文存储**（需参与 SUM 统计，加密后无法聚合），在接口层按权限控制是否下发；无权限时字段为 `null`，前端不展示。
4. **可见角色**：系统管理员、案件管理员、部门负责人（本部门）、承办人（本人）可见敏感字段；协办人、会签人、阅知人默认不可见。
5. **编辑权限**：仅承办人/案件管理员在未结案、未归档且状态允许时编辑。
6. **审计员**：仅查看脱敏后的审计日志，不返回案件业务明细。
7. **导出**：台账/统计表导出按当前用户数据权限取数，并写入导出人与导出时间留痕。

## 8. 数据保留、备份与本地化存储

1. 审计日志默认保留 1 年（`gsms.audit.retention-years`，环境变量 `AUDIT_RETENTION_YEARS`），超期记录由 `AuditRetentionService` 每天 02:30 分批（1000 条/批）清理，服务启动时补做一次；清理动作本身写审计。仅允许按保留策略清理，不提供手工单条删除。
2. 文档版本逻辑删除，不物理删除；归档案件只读，仅允许查询与受控下载。
3. 本地数据目录（生产服务器实测）：数据库文件位于 MySQL 5.7 安装目录下的 `data` 目录（不迁移，避免影响同机其他库）；其余数据统一置于 `C:\GSMS\data`：

```text
C:\GSMS\data\
  files\            # 默认文档存储目录（对应 file_path 中的 /files）
  tmp\              # 上传临时目录、预览缓存
  logs\             # 应用日志、Nginx 日志
  backup\
    mysql\          # mysqldump 输出
    files\          # 文档目录增量/全量包
```

生产服务器仅有 C 盘（可用约 300GB），文档、日志、备份统一落 `C:\GSMS\data`，并与系统盘增长一并监控；MySQL 5.7 若需整体迁移，按“停 `MYSQL57` 服务 → 改 `my.ini` 的 `datadir` → 迁移 Data 目录 → 启服务并校验”执行，迁移前须全量备份。

4. 每日备份 MySQL 与文档目录，备份文件加密；保留周期按企业制度执行，审计日志按 1 年策略自动清理。备份命令（Windows 任务计划程序，每日 02:00）：

   ```bat
   "C:\Program Files\MySQL\MySQL Server 5.7\bin\mysqldump.exe" -uroot -p^<密码^> ^
     --single-transaction --routines --triggers --default-character-set=utf8mb4 ^
     case_system > C:\GSMS\backup\case_system_%date:~0,4%%date:~5,2%%date:~8,2%.sql
   ```

   参数说明：`--single-transaction` 保证 InnoDB 一致性快照且不锁表；`--default-character-set=utf8mb4` 防止中文注释与数据在 GBK 控制台下损坏。
5. 提供恢复脚本与恢复演练说明，恢复后校验案件、文档、审计日志一致性；演练使用独立库 `case_system_restore`，不覆盖生产库。

  node_name VARCHAR(50) NOT NULL,
  sort_no INT NOT NULL,
  time_limit VARCHAR(20) NULL,
  main_role VARCHAR(100) NULL,
  key_material VARCHAR(300) NULL,
  sys_action VARCHAR(300) NULL,
  allow_rollback TINYINT NOT NULL DEFAULT 1,
  next_codes VARCHAR(200) NULL COMMENT '后继节点码，逗号分隔；空则按内置流程',
  enabled TINYINT NOT NULL DEFAULT 1,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_flow_status (flow_key, status_code),
  KEY idx_flow_sort (flow_key, sort_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='流程节点定义表';

CREATE TABLE case_member (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  case_id BIGINT NOT NULL,
  user_id VARCHAR(32) NOT NULL,
  member_role VARCHAR(30) NOT NULL COMMENT 'OWNER/HANDLER/CO_HANDLER/COUNTERSIGN/READER',
  join_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_case_user_role (case_id, user_id, member_role),
  KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='案件成员表';

CREATE TABLE case_document (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  case_id BIGINT NOT NULL,
  doc_name VARCHAR(200) NOT NULL,
  doc_type VARCHAR(50) NOT NULL,
  file_path VARCHAR(500) NOT NULL COMMENT '本地相对路径',
  file_size BIGINT NOT NULL,
  file_hash VARCHAR(64) NULL,
  version INT NOT NULL DEFAULT 1,
  parent_id BIGINT NULL,
  upload_by VARCHAR(32) NOT NULL,
  upload_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  watermark TINYINT NOT NULL DEFAULT 1,
  sensitive_flag TINYINT NOT NULL DEFAULT 0,
  deleted TINYINT NOT NULL DEFAULT 0,
  KEY idx_case_id (case_id),
  KEY idx_doc_type (doc_type),
  KEY idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='案件文档表';

CREATE TABLE deadline_reminder (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  case_id BIGINT NOT NULL,
  node_code VARCHAR(50) NOT NULL,
  node_name VARCHAR(100) NOT NULL,
  deadline_type VARCHAR(20) NOT NULL,
  deadline_date DATE NOT NULL,
  remind_days INT NOT NULL DEFAULT 3,
  status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
  handler_id VARCHAR(32) NOT NULL,
  overdue_level INT NOT NULL DEFAULT 0,
  overdue_reason VARCHAR(500) NULL,
  supervise_opinion VARCHAR(500) NULL,
  KEY idx_case_id (case_id),
  KEY idx_deadline_status (deadline_date, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='期限提醒表';

CREATE TABLE audit_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id VARCHAR(32) NOT NULL,
  user_name VARCHAR(50) NOT NULL,
  operation VARCHAR(100) NOT NULL,
  module VARCHAR(50) NOT NULL,
  business_id VARCHAR(64) NULL,
  request_ip VARCHAR(64) NULL,
  request_params TEXT NULL,
  result VARCHAR(20) NOT NULL,
  trace_id VARCHAR(64) NULL,
  before_data TEXT NULL,
  after_data TEXT NULL,
  operate_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_id (user_id),
  KEY idx_operate_time (operate_time),
  KEY idx_module_business (module, business_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='审计日志表';

## 11. 与可选组件关系

| 组件          | 数据库影响                           | 关闭时策略                |
| :------------ | :----------------------------------- | :------------------------ |
| Redis         | 不改变核心表                         | 使用本地缓存/数据库令牌   |
| Elasticsearch | `audit_log` 异步同步                 | 使用 MySQL 检索审计日志   |
| RabbitMQ      | 通知/审计异步                        | 使用数据库异步任务/线程池 |
| MinIO         | `case_document.file_path` 存对象 Key | 使用本地磁盘相对路径      |
| HR 接口       | `sys_dept`、`sys_user` 可同步        | Excel 导入/手动维护       |
|               |                                      |                           |
